## Layout

- **`asm/`**: the four task sources, generated by `gen/gen_s2.py`:
  `ring_e1.s` (E1), `ring_hold.s` (E4, E5), `pa_read.s` (E2a read pass), `pa_write.s` (E2a
  writes, sa67 and sa68 only)
- **`bins/`**: their blobs, assembled and verified by the LANDED `tools/fwtask/fwtask.py`
  (imported read-only; its verifier is the kernel's table); `blobs.json` sizes and sha256
- **`tables/STAGE.json`**: one job table a stage (what runs); `TABLES.md` the readable view
- **`predictions/STAGE.tsv`**: frozen predictions `case quantity value model set`;
  `e1-baseline-order.tsv` the offline first-rise orders of E547 (Q111's baseline, events 0d)
- **`score/score_s2.py`**: the scorers (standard library), one `SUMMARY:` line a stage; with
  `--gate` they write the gate file and exit 0 only when the gate is open
- **`run/s2_run.py`**: the laptop-side stage runner (python3 stdlib, `sudo -n python3`); it
  imports the landed `fwtask_run.py` (copied to `~/s2/run/`) for the page, the registers, arm,
  reset and gate, and calls none of its polling commands
- **`run/s2.sh`**: the Mac-side session driver (gates, health, copies, scorer)
- **`run/stage_s2.sh`**: copies runner, layout, tables, blobs, `LAPTOP.sha256` and the landed
  `fwtask_run.py` to `~/s2/` and checks them there; builds nothing
- **`run/freeze_s2.sh`**, `FROZEN.sha256`, `PREDICTIONS.sha256`, `LAPTOP.sha256`: the freeze
- **`run/guard_s2.sh`**, `run/guard_py.py`: static checks (the forbidden list, wait loops,
  unprivileged debugfs access, test-only overrides, the sources' writes, the tables' knobs)
- **`tests/`**: `sim_s2.py` (the blobs in sgx-sim: encodings and control flow, not hardware),
  `test_scorer.py` (every shape and void rule on synthetic pages), `run_mock.py` (28 end-to-end
  tests: the session, each gate, each stop rule, the guard, the review fixes), the mock
  (`mockfw/`, `fake_tool.py`, `fake_health.sh`, `shims/`; the sudo shim maps `/sys/kernel/debug`
  and `/home/jtorra/` into the mock so the scripts keep the laptop's literal paths)
- `work/try.s`: a scratch assembly check (not part of S2)

Python: `~/src/scratch/resgx545/closing/pixel-faults/.venv/bin/python` (scorers, generator,
tests).  The laptop runner needs only the laptop's python3.

## Order, gates and stop rules (decided by the user)

```
run/guard_s2.sh                       # static checks
../pixel-faults/.venv/bin/python gen/gen_s2.py && run/freeze_s2.sh freeze   # only after a change
run/stage_s2.sh                       # once: copy to ~/s2 and check (no build)
run/s2.sh                             # e1c e1j e2r e2w e4c e4h e4l e5c e5t, gated
run/s2.sh --from STAGE                # resume after an analysis (the gate file must be OPEN)
```

| stage | rows | blob | then |
|---|---|---|---|
| e1c | E1 rows 1-3 (controls) | ring_e1 | gate G1 |
| e1j | E1 rows 4-8 (fill, copy, tri 64, tri 256 -n 3, partial) | ring_e1 | exit 0, health |
| e2r | E2a read pass x3 | pa_read | gate G2 |
| e2w | E2a: ctl, sa67 x3, sa68 x3, restore x2 | pa_write | exit 0, health |
| e4c | E4 row 1 (no hold, 16 ticks) | ring_hold | gate G3 |
| e4h | E4 rows 2-4 (0.7, 6.5, 20 ms) | ring_hold | gate G4 |
| e4l | E4 row 5 (100 ms) | ring_hold | gate G5 |
| e5c | E5 rows 1-2 (100 ms control, kick in a hold) | ring_hold | gate G6 |
| e5t | E5 row 4, then row 3 (triangle in a hold) | ring_hold | end |

- G1: the quiet 50 ms window logs nothing (3/3), the 8 ms window logs its ticks (2/2), each kick
  logs exactly one non-tick entry with the kick's words, pa0 0 and pa1[23:0] 0x100 (3/3, fit: S2
  run 1; E538's words were the tick after the kick), and the quiet window after the kicks logs
  nothing (q50k, 2/2).  See PREFLIGHT.md section 7.
- G2: sa66 = 0x01061a70 in 3 of 3 valid read passes (the only way `pa_write` is ever armed)
- G3: 16 tick entries on the 25000 grid (3/3)
- G4, G5: every hold valid (done, run id echoed, the knob in its band), tick and health fine;
  the prediction is NOT part of the gate
- G6: the 100 ms control reproduces e4l's shape (2/2) and the three kicks are valid

Every gate is computed by the scorer (`score_s2.py STAGE out/STAGE --gate`), written to
`gates/STAGE.gate` with the stage's run id (`GATE e2r OPEN run=<id>`), copied to the laptop, and
checked twice: by `s2.sh` and by the laptop runner, which refuses the next stage unless the gate
is OPEN and names the run id of its own `~/s2-out/<prev>/stage.json` (exit 0).  `stage_s2.sh`
overwrites every gate with NONE, and `s2.sh` sets a gated stage's own gate to NONE before running
it, so no gate of an earlier run counts.  `pa_write` is armed only in
e2w, and e2w runs only behind the e2r gate.

Runner exits: 0 done; 1 preflight (not root, a file not frozen, the gate not open, srcversion,
missing debugfs file, knobs not at their defaults, no tool); 3 a watchdog/lockup/BUG line (nothing
else touches the GPU); 4 a stop (not done, tick not advancing over three reads, unhealthy, a bad
log line, a failed client job, an unhealthy or dirty arm, an e2w restore skipped or not read back,
any unexpected exception): one cleanup dumps the page and debugfs state, resets and gates; 5 the
reset or gate after a stop not exact; 6 the tool did not return (nothing else touches
the GPU); 7 a table value off the allow-list; 9 a knob read back differs.  E5 row 3 only: a held
triangle that does not complete is a result (`stuck`): the page is read, hold_recovery released,
reset, gate, the row not repeated, the stage ends.  `s2.sh` adds 20 (freeze changed), 21 (the
laptop's `LAPTOP.sha256` is not this freeze's), 30-35 (health after a stage), 33 or 38 (a
watchdog, or an unreported hung/recovery/fault line, in the stage's `kernel.log`), 37 (copy), 40
(gate closed), 41 (scorer refused or failed), warns when e2w stops (sa67/sa68 may still hold the
S2 marker), and bounds every ssh with a perl alarm (255 or 142: a freeze, boot nothing).  Any of
them ends the session.  The scorer also refuses (`cannot tell`) a stage whose `env.json` hashes
are not the Mac's frozen table and blob.

## Per stage: control, knob proof, fit or held out

- **e1c**: controls reproduce E538's quiet window and E532's tick words (fit, earlier data); the
  kick control and q50k are a fit of S2 run 1; held out: the kick's pa2 range and phase, the count
  step and values, the clock control (stamps 25001 apart, E009).  Knob proof: the quiet window with
  the slot filter logs nothing while the
  window without it logs ticks; every job's ring is read twice after the close and must not change.
- **e1j**: all held out (H1 E155 and H2 E146 are readings of the firmware, never fitted to ring
  data).  Knob proof: the window-0 re-read; the partial rows must print `overflowed`
  (render_pb_pages 0x30 read back, put back, both marked).  Instrument control that can fail:
  every entry's slot equals PDS #13's dispatch of its own words (E146).
- **e2r**: held out: sa66 = 0x01061a70 (an inference from E537 and E532, events 0a); control:
  pa0 = 2.  Knob proof: the run id echoed, state 3 (the next pass ran).
- **e2w**: held out: pa3/pa4 follow sa67/sa68 (H-D).  Knob proof: sa67/sa68 read back the mark in
  the same pass (void otherwise).  Control: the read pass again (sa66).
- **e4c**: control (16 tick entries on the grid).  **e4h, e4l**: held out: H-ONE (the proposal's
  pick, fitted post hoc to E539's three lags of 1.9 to 2.2 ticks: fit for n = 100000, an
  extrapolation for 300000 and 1500000).  Knob proof: exit minus entry stamp within 0.7 to 1.5
  times E539's rate for n.
- **e5c, e5t**: no favourite between QUEUED and LOST (frozen discriminants only).  Knob proof:
  the hold band, STATE busy read once before the trigger, and for the triangle its render time
  longer than the no-hold control (overlap shown).

The scorers treat missing, empty, truncated or stale data (a record of an earlier run of the
stage) as void, never as a pass; a stage with too few valid jobs is `cannot tell`.
